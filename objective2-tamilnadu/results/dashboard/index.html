A design passes only if its evening-window gain exceeds the measured repeatability band — a gain smaller than the band is noise, not a benefit. The band combines year-to-year scatter with timestep, node-count and material-property perturbations. Select years are 2021–2023; the held-out years 2011–2015 were untouched until the single permitted test run.

The three edge cases, and how each is handled

Capsules will not pack. Past a certain radius the capsules cannot leave a 5 % flow passage through the tank, and at small radii the count needed for a given PCM volume overruns the packing rule. The geometry engine rejects these before any simulation runs, so they cost nothing and can never be selected.

The PCM overheats. More PCM stores more heat, but a tank that stores too much runs the PCM past 65 °C, where the material is no longer rated. This is a hard constraint on the select years, not a penalty — a design that breaches it in any year is out, however well it scores.

The gain is real but too small to trust. A design whose gain is smaller than the repeatability band is indistinguishable from the plain tank given our own measurement scatter. Those are reported as no meaningful benefit rather than as wins.

The optimiser does not evaluate every design — each one costs a full year of simulation. It fits a surrogate model to what it has already seen, uses that to guess where the good designs are, simulates a handful there, and refits. These charts are that loop happening: as the training set grows, the front improves and the surrogate's error falls.

A second search, run independently

A Gaussian-process Bayesian optimiser was run against the same problem as a cross-check. It starts with 20 quasi-random Sobol designs, then picks each next design by expected improvement. The step shape is the signature of the method: long flat stretches where it explores, then a jump when it finds something better.

Turning the flow rate up in Fluent

Flow rate is one of the four parameters the optimiser searches, so it was swept in CFD too: the same capsule, the same PCM, the same 70 °C water, with only the inlet velocity changed across the design space's low, middle and high ends. Faster flow carries more heat past the capsule each second, but gives each parcel of water less time to hand it over — so the benefit should fade rather than keep climbing.

This is an independent check on the optimiser rather than a new result. The CFD never saw the tank model, the weather or the demand profile; it was given one capsule and three flow rates. That it bends in the same place the optimiser settled is the useful part.

Why the ordering is believable

The curves are ordered by physics three independent ways. n-Pentacosane has the lowest melt point, starts melting earliest and melts most. n-Hexacosane and RT57HC share a melt point, and the one with higher thermal conductivity melts more. PureTemp 58 has both the highest melt point and the lowest conductivity, so it melts least.

The solver uses first-order upwind, which is more numerically diffusive than second order, so these melt fractions are conservative. A second-order run of the three PCMs that would solve under it reached higher fractions in the same order. First order is used because it is the only setting under which all four PCMs solve, and a comparison is only meaningful when every run shares the same settings. Read the ordering, not the absolute values.
