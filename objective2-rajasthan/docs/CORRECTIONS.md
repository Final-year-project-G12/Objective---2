# Corrections log - Rajasthan Objective 2 common-plant rebuild

Written 2026-11-26. Each entry: what was wrong or changed, how it was found, what was done, and whether any result was affected. Entries are in order of discovery (2026-11-24 to 2026-11-26). Older corrections of the legacy v3 pipeline are in `docs/PROGRESS.md` and `docs/README.md` and are not repeated here.

## C1. 100 L/day showed no PCM benefit (decision, not a bug)

- **Found:** the plant scan (`scripts/r12_plant_scan.py`, explore years 2017-2018 only) gave a paired g_window of -1.1 / -3.6 / -4.6 kWh/yr at 100 L/day for the fixed design, because the plain tank already meets 98-99 % of the demand.
- **Done:** the demand was changed to 175 L/day (same as Tamil Nadu) and declared in `docs/REBUILD_COMMON100L.md` section 8 and `docs/PLAN_DEVIATIONS.md`. The L3 verification was re-run on the new plant, and 60 stale 100 L/day result files were moved to `results/archive_100Lday_2026-11-24/` so the resuming DOE and grid scripts could not reuse them.
- **Effect:** every PCM result depends on this choice. It was made after seeing a result on explore years, and that is stated wherever the results are quoted.

## C2. Ported Uttarakhand code had state-specific leftovers

Rajasthan's rebuild scripts were ported from the Uttarakhand rebuild. Four leftovers were found and fixed:

| file | leftover | fix |
|---|---|---|
| `scripts/r12_plant_scan.py` | imported `STATE` from a `config` module that does not exist here | `STATE = "rajasthan"`; demand base set to the current file (`BASE_L`) |
| `scripts/r10_supplementary.py` | plant cases were relative to a 100 L/day base | cases are absolute (70, 100, 150, legacy 300 L/day on 2.5 m2, a 150 L tank) |
| `src/handoff/build_obj3_contract_common100L.py` | Uttarakhand wording; asserted a 100 L/day plant and a water-only result; read a key (`Tm_target_C`) that the Rajasthan manifest does not have | reworked for 175 L/day and the PCM result; key replaced by `Tm_C_by_shortlist` |
| `scripts/r9_rebuild_figures.py` | four regimes (the source script looped over four regimes; Rajasthan has three); a title claiming "more PCM delivers less" | three regimes; neutral title |

`pipeline.py` docstring lines still said 100 L/day and a 720-run grid; corrected to 175 L/day and the actual 240-design grid. Effect on results: none (no result file was produced by the faulty lines; the figure and contract stages failed, and were fixed before they ran to completion).

## C3. Repeatability band: no deviation needed

During planning it looked as if the funnel might have to switch to Tamil Nadu's "core band" because the demand term is large. The band file shows that Rajasthan's full pre-registered band (`wp6_band.csv`: 39.8 / 24.6 / 24.3 kWh/yr for g_window) is what the funnel used, and the chosen designs clear it with their worst anchor. Nothing was changed; Tamil Nadu's deviation does not apply here.

## C4. Misread worst-anchor numbers in a status message

A status message on 2026-11-25 quoted worst-anchor figures of 154.7 / 57.9 / 122.8 for the test. Those are the bottom-anchor g_annual values. The worst-anchor g_window values are 145.2 / 52.6 / 115.4 (`results/o2_test_2006_2010.csv`). `docs/RESULTS_COMMON_PLANT.md` uses the correct ones.

## C5. Supplementary stage out-of-memory failure

The first supplementary run stopped with `ArrayMemoryError` while a parallel pytest run was using memory. It was re-run alone with `--jobs 2` and finished. No partial output was kept as a result.

They carry a LEGACY banner and were not rewritten; their numbers are not the current results. `docs/04_RESULTS.md` is generated by `scripts/g12_results_doc.py` for the legacy results, and regenerating it would remove the banner.
