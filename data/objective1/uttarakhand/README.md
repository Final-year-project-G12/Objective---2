# Uttarakhand — Objective-2 Input Data

**Status: not started.** Uttarakhand's Objective-1 pipeline (climate clustering + MCDM
ranking) has not produced any outputs yet. This folder currently holds only the shared
PCM property sheet and the bookkeeping files that record what's still owed.

## Folder layout

```
uttarakhand/
  pcm_properties.csv   the one real data file present so far
  MANIFEST.json         machine-readable record of what's present vs. missing
  _STATUS.md            human-readable version of the same
```

## What's missing before O2 can be frozen for Uttarakhand

Per `_STATUS.md` / `MANIFEST.json`, the upstream Objective-1 pipeline for Uttarakhand
still needs to produce:

- `climate_signature_uttarakhand.csv` — per-point climate indices (`Tm_target_C`,
  `L_required_kJ_per_kg`, etc.) — the equivalent of Rajasthan's `climate_signature_
  rajasthan.csv` / Tamil Nadu's `climate_signature_tamilnadu.csv`.
- `cluster_assignments_levelA_uttarakhand.csv` — which climate regime each point
  belongs to.
- `cluster_profiles_uttarakhand.csv` — per-cluster population-weighted design targets
  (what O2's DOE actually reads).
- `mcdm_rankings_uttarakhand.csv` — the PCM ranking table (TOPSIS/PROMETHEE/VIKOR/GRA +
  consensus) per climate cluster.
- `weather_files/` — per-regime representative weather (the `weather/` subfolder
  Rajasthan and Tamil Nadu both have).

There is also no `raw_weather/`, `weather/`, or `demand/` subfolder yet — those are
built only after the four files above exist, the same way Rajasthan's and Tamil Nadu's
were.

## How to unblock this

1. Run Uttarakhand's upstream Objective-1 climate-clustering + MCDM pipeline (grid
   points → climate signature → clustering → feasibility filter → MCDM ranking),
   following the same script sequence as the Rajasthan/Tamil Nadu pipelines. Note
   Uttarakhand is hilly terrain (unlike Rajasthan/Tamil Nadu/Assam) — check whether the
   population-grid and elevation handling in `00a_build_population_grid.py`-equivalent
   needs adjustment for that before assuming the same grid logic ports as-is.
2. Re-run `build_obj1_frozen_package.py` for Uttarakhand — it is idempotent, so it will
   pick up whichever of the missing files now exist and update `MANIFEST.json` /
   `_STATUS.md` accordingly.
3. Once `climate_signature_uttarakhand.csv` and `cluster_profiles_uttarakhand.csv` exist,
   run the Objective-2 build scripts (`build_input_package.py`, `build_regime_weather.py`,
   `build_demand_profile.py`) with `config.py`'s `STATE = "uttarakhand"` to populate
   `weather/`, `demand/`, and `raw_weather/` the way they're populated for Rajasthan.
